## 1. 專案目的

UCC（林森、昆明、廣慈三站）支援護理人力每月開放線上預班。名額有限、開放瞬間大家同時搶，手動操作很難搶到想要的班。

本工具讓使用者：

1. 事先在介面上排好「願望清單」（日期／院區／白班或夜班）
2. 開放當下 **對齊國家標準時間、準時（不提早）** 自動送出
3. 診別依偏好順序 **診1 → 診2 → 備援**，被搶走立刻換下一個
4. 送出後向系統查詢、確認自己名下的預約

> 只登記本人（或經本人同意）的班，且是自己要上的班。

### 原始碼中影響速度的關鍵發現

- 畫面上的「未開放預約」是用 **使用者電腦的時鐘**（`new Date()`）判斷，而且要 **重新點日期才會更新**。08:59 打開的頁面，到 09:00 仍顯示鎖住。
- 每次預約成功後，畫面會重新下載 **全部系統資料**（實測 3.5–5 秒）。
- 因此「在畫面上點來點去」很慢。本工具改為在網頁內 **直接呼叫 `createBooking`**，多個日期同時送出。

### 實測速度

| 動作 | 時間 |
|---|---|
| 開啟系統網頁到可用 | 2.7–3.0 秒 |
| 讀取全部資料 `getInitialData` | 3.5–5.1 秒 |
| 預約一次 `createBooking` | 尚未實測（推估 1–3 秒，尖峰可能更慢） |

## 3. 運作流程

```
開放前 40 秒      開啟系統網頁、等 google.script.run 可用
                  讀取並保存系統原始碼，比對是否改版
                  確認 createBooking 參數格式沒變
                          │
09:00:00.000      （國家標準時間，不提早）
                          │
                  所有日期「同時」送出（日期由後往前排）
                  ┌───────────────┬───────────────┬───────────────┐
                  │ 12/27 診1     │ 12/20 診1     │ 12/13 診1     │
                  │  └ 被搶→診2   │  └ 成功 ✓     │  └ 被搶→診2   │
                  │     └ 成功 ✓  │               │     └ 成功 ✓  │
                  └───────────────┴───────────────┴───────────────┘
                          │
                  向系統查詢本人預約紀錄並列出
```

### 每一天的處理規則

1. 同一天的清單項目依序嘗試；每一項依 **診別順序**（預設 診1→診2→備援，可個別改 診2 先）
2. 伺服器回覆：
   - **成功** → 這天完成
   - **已被預約／額滿** → 立刻送下一個候選
   - **這天已有預約（一天一班）** → 這天完成
   - **尚未開放** → 每 0.3 秒重試（最多 90～120 秒）
   - **帳號或密碼錯誤** → 全部停止並回報
   - **連線錯誤** → 同一格重試 2 次
3. 同一天放多筆 = **備選順序**，第一個成功就停（因為一天只能一班）

### 時間校正

- 優先使用 **國家標準時間 NTP**（`time.stdtime.gov.tw` 等）
- NTP 被擋（如雲端）時，改用 Google 伺服器 HTTP 時間，多次取樣交集，誤差約 ±0.1–0.2 秒
- 最後 0.2 秒忙等，送出時間誤差約數毫秒
- 開放時間一律以 **台灣時間（UTC+8）** 計算

## 6. 使用方式（圖形介面）

1. **① 點選日期**：切換月份，點日期（可多選；有 全選／週末／平日／清除）
2. **② 選班**：勾院區、白班／夜班 → **➕ 加入清單**
3. **③ 願望清單**：
   - 欄位：日期、星期、院區、班別、結果
   - **⇄ 診2先**：選取的列改為 診2→診1→備援
   - 上移／下移／刪除／清空
   - **匯出雲端**：產生 `wishes.json`
4. **④ 開放時間**：例 `2026-11-14 09:00:00`；大時鐘顯示校正後的標準時間與倒數
5. 按鈕：
   - **⏰ 開始排程**：時間到準時送出
   - **▶ 立即執行**：開放時間內直接送出
   - **🧪 測試（不送出）**：檢查系統、ID、清單，不會預約
   - **🔍 手動操作並錄下原始碼**：開網頁讓你手動操作，程式在旁邊錄
   - **■ 停止**
6. 按開始時跳出 **ID／密碼視窗**：
   - 可勾「顯示密碼」檢查，下方顯示 `ID：[…]`、`密碼：[…]（N 個字）`，前後有空白會警告
   - **只在本次有效，不存檔**

## 7. 使用方式（無介面／雲端）

`wishes.json` 格式（不含帳密）：

```json
{
  "open_time": "2026-11-14 09:00:00",
  "wishes": [
    {"date": "2026-12-13", "site": "林森", "shift": "白班", "clinics": ["診1", "診2", "備援"]},
    {"date": "2026-12-20", "site": "林森", "shift": "白班", "clinics": ["診2", "診1", "備援"]}
  ]
}
```

測試（不送出，只需 ID）：

```bash
UCC_ID=員編 python ucc_run.py wishes.json --dry-run
```

正式（等到 `open_time` 準時送出）：

```bash
UCC_ID=員編 UCC_PW=密碼 python ucc_run.py wishes.json
```

開放時間內立即送出：

```bash
UCC_ID=員編 UCC_PW=密碼 python ucc_run.py wishes.json --now
```

未設定環境變數時會詢問（密碼不顯示）。一次執行一個帳號；多人就各跑一個。

## 10. 已知限制與風險

- **`createBooking` 的伺服器回應時間與錯誤訊息未實測**：錯誤分類（已被預約／一天一班／尚未開放／密碼錯誤）依前端程式與常見寫法推測，伺服器實際文字可能不同；未知訊息會當作失敗並換下一個候選。
- **伺服器端是否檢查開放時間未知**（只看得到前端）。本工具一律準時送出、不提早。
- **密碼只能在正式送出時驗證**；測試模式只能確認 ID 存在。
- 開放瞬間大量人同時送出，Google Apps Script 可能變慢或排隊。
- 系統若改版（函式名稱或參數改變），程式會在執行前警告；需依 `source_history/` 的新版原始碼調整。
- 排程觸發可能有幾分鐘延遲，所以 08:50 啟動，預留 10 分鐘準備。
- 電腦版排程期間不可睡眠、不可關閉視窗。

## 11. 資安與隱私

- 帳號密碼只存在記憶體（GUI）或對話中（雲端），不寫入檔案、git 或排程內容；保存的網頁與網路紀錄中密碼會被遮蔽。
- **建議修改密碼**：目前使用的帳號密碼與員編相同，知道員編就能猜到密碼。系統內有「更改密碼」功能。
- **系統本身的資料外洩問題**：`getInitialData` 不需登入就回傳全部人員（約 126 人）的員編、姓名、電話，以及所有預約紀錄。建議轉告系統管理者改為登入後才提供，或只回傳必要欄位。本工具只讀取自己的資料，不輸出他人資訊。
